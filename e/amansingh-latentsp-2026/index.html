本期速览 · Overview

Arca 的 Aman Singh 讲述这家 AI 原生财富管理公司如何用模型无关的智能体框架，在人类顾问背后完成长周期金融工作。

Aman Singh of Arca explains how an AI-native wealth management firm uses model-agnostic agent harnesses to run long-horizon financial work behind human advisors.

要点 · TL;DR

  • AI 替代的是顾问的后台工作而非顾问本身，共情仍由人提供。
    AI replaces advisor's back-office work, not the advisor; empathy stays human.
  • 掌控自己的执行框架和运营知识，别把智能外包给托管代理。
    Own your harness and operational knowledge; don't outsource intelligence to managed agents.
  • 代理会 24/7 主动提醒人，颠覆了通常的人对代理的交互模式。
    Agents proactively prompt people 24/7, flipping the usual human-to-agent interaction.

核心观点 · Key points

  • AI 的作用是替代顾问周边的工作，而非顾问本身；客户体验到的仍是人类的共情。
    AI's role is to replace work around the advisor, not the advisor; clients experience human empathy.
  • 智能体负责分析与规划，但资金流动和客户沟通需要人类在环。
    Agents handle analysis and planning, but money movement and client communication require human-in-the-loop.
  • 内部基准而非外部基准指导模型选择；保持模型无关性以保留选择权。
    Internal benchmarks, not external ones, guide model selection; being model-agnostic preserves optionality.
  • 默认可审计：每个智能体和人类操作都生成变更日志，用于合规和智能体循环。
    Auditability by default: every agent and human action produces a change log for compliance and agentic loops.
  • 长周期任务依赖持久记忆系统和每日反思，以跨天维持上下文。
    Long-horizon tasks rely on persistent memory systems and daily reflection to maintain context across days.
  • 拥有 harness 和操作知识就是拥有你的智能；不要将其外包给托管智能体。
    Owning the harness and operational knowledge is owning your intelligence; don't outsource it to managed agents.

反共识 · Contrarian takes

  • 智能体提示人的次数多于人提示智能体；服务是 24/7 主动的，而非被动的。
    Agents prompt people more than people prompt agents; the service is proactive 24/7, not reactive.
  • AI 原生公司与使用 AI 工具的服务公司有本质区别；前者为智能体标准化工作流程。
    Being an AI-native firm differs fundamentally from a services firm using AI tools; the former standardizes work for agents.
  • AI 能让合规比人类做得更好，因为它不知疲倦地查找不合规内容。
    AI can make compliance better than humans because it is tireless at finding non-compliant mentions.
  • 让智能体直接修改提示词有风险；它们会产生糟糕的过拟合提示，缺乏元泛化能力。
    Letting agents make prompt changes directly is risky; they produce nasty, overfit prompts without meta-generalization.
  • 外部基准宣称模型表现优异，未必能转化为真实的业务性能。
    External benchmarks claiming great things for a model may not translate to real business performance.
  • 沙盒代码被转换为严格格式，原始代码在到达后端前被丢弃。
    Sandbox code is translated into a strict format and the original code discarded before reaching backend.

恢复长时间运行的代理任务 Restoring long-running agent tasks

Host

你提到这些流程往往要 10 天，或者至少比现在大多数智能体的运行时间更长。那么当一个智能体在开始任务几天后才恢复执行时，你如何恢复——如何确认这个计划仍然符合客户的需求？

You mentioned that these processes tend to be 10 days or at least a longer running time than most agent stuff these days. So when an agent resumes a task maybe days later than they started it, how do you restore — how do you check that the plan still fits the client's needs?

Aman

好，这个问题很有意思。我们有大量这类信号，就像我在演讲中描述的那样。比如你可以想象有一个邮件线程正在收到回复，有人在里面讨论，对吧？任何新增的回复都会交给同一个正在阅读该邮件线程并做出反应的智能体。但一个全新的信号——比如中途打进来的一通电话——是一个全新的信号，不依附于任何正在进行的流程。于是会有一个新的智能体被唤醒，去弄清楚这意味着什么。而它们理解当下正在发生什么的方式，是我们的内部记忆系统。所以我们为每个客户维护这种持久状态：现在正在发生什么、我们要服务什么、谁负责什么、到目前为止发生了什么、我们在追踪什么后续事项——接下来几天需要立即做什么、长期在追踪什么、哪个人负责哪个动作。所有这些都由我们的记忆系统追踪，我们的智能体也会向其中贡献信息。但同时还有一个类似“做梦”的过程，它会反思与客户 Richard 相关的世界状态，并能够更新这些记忆系统，以持久化长周期任务。所以那个收到新信号的智能体会迅速了解客户当前的情况，它会知道：“好，我们实际上正在执行一笔大额税单。”它也能看出：“好，我的信号和那笔税单有关，那我来为那个世界的状态做点贡献。”

Yeah. So this is an interesting one to think about. We have tons of these signals, like I described in the talk. Some are, for example — you can imagine there's an email thread that is receiving responses and there's chatter happening, right? Any additional response to that goes to the same agent that's reading that email thread and reacting to it. But a fresh signal — like a phone call that was made in the middle — is a brand new signal that isn't attached to any other ongoing process. And so a fresh agent wakes up to figure out what this means. And the way they understand what is happening right now is our internal memory systems. So we have this persistence for every client: what is happening right now, what are we trying to service, who owns what, what has happened so far, what are we tracking for next — what needs to happen immediately in the next couple of days, what are we tracking for the long term, which individual is responsible for which action. All of this is being tracked by our memory systems that our agents contribute to. But also, there is a kind of really dreaming process that reflects on the state of the world as it relates to Richard, the client, and is able to update these memory systems to persist long-horizon tasks. So that agent that received a new signal quickly ramps up on what the situation is with the client, and it'll know, "Okay, we're actually executing a big tax bill." And it'll be able to see, "Okay, my signal relates to that tax bill, so let me contribute to the state of that world."

安全护栏与确定性检查 Safety guardrails and deterministic checks

Host

你能不能谈谈你在产品里构建或接入的一些安全方面的机制，显然是为了确保过程中不会损失任何资金？

Can you talk a little bit about the safety aspects that you've maybe built onto your product or harnessed, to make sure obviously that no money is lost along the way?

Aman

好。我们所有的安全限制都是完全确定性的，它们把决策权从智能体手中拿走。比如某些工具允许智能体自己执行。如果是简单的记录类工具，它就会执行。另外，每当调用会写入数据的工具时，我们都会对该动作运行基于 LLM 的验证。这些是快速的 LLM 调用，会分析对我们数据库的每一次写入。所以这是我们运行的又一层验证。然后我们还会摄入大量外部信息。比如进来的邮件、进来的文档、打进来的电话，这些都是提示注入的目标。所以我们在边缘运行验证，检测某些类型的提示注入是否存在。然后任何时候出现数据离开我们系统的情况——比如最明显的网页搜索，或者我们给 Richard 发日历邀请，对吧？那是外部数据——我们既有确定性检查，检测我们已知属于 PII 的某些信息是否存在，也有小模型的共识机制，确保没有任何数据外泄的企图。所以我们在 harness 里内置了大量不同的护栏，原则是我们希望在能力的边缘进行遏制，而不是更早。

Yeah. So all of our safety restrictions are fully deterministic and they take the decision-making off the agent's hands. So for example, certain tools let the agent execute the tool itself. So if it's a simple record-keeping kind of tool, it will execute it. We also — every time a tool is called that writes data, we have LLM-based verification running on that action. These are fast LLM calls that analyze every single write to our database. So that's another layer of verification we're running. And then we also ingest a lot of external information. So there are emails coming in, documents coming in, phone calls being made, which are targets for prompt injection. So we run verifications at the edges that detect the presence of certain flavors of prompt injection. And then anytime there is a case where data leaves our system — for example, in a web search in the most obvious case, but also if we're sending a calendar invite to Richard, right? That's external data — we have both deterministic checks on the presence of certain information that we know is PII, but also a consensus of small models that ensure that there isn't any kind of data exfiltration being attempted. So we have tons of different guardrails built into the harness, with the principle that we want to contain them at the edges of capability and not earlier than that.

监管与可审计性 Regulation and auditability

Host

而且因为你们身处金融行业，在使用技术方面是否有某些必须遵守的监管要求？还是说更多是关于结果以及你们与客户打交道的方式？

And because you're in the financial industry, are there certain regulations that are required that you have to keep to in terms of the technology that you're using? Or is it more about outcomes and the way you deal with clients?

Aman

对，行业关心的是结果，但合规关心的是可审计性，对吧？所以我们的系统做到默认可审计。智能体采取的每一个动作都会产生变更日志：改了什么、谁改的、来自系统的哪个部分、什么时候改的。顺便说一句，这不仅适用于智能体，也适用于人类操作者。所以如果你在 UI 里改了影响客户的东西，我们也会记录该动作。这让我们既能默认可审计，也支撑了我们的一些智能体能力——我们追踪的 UI 变更同样可以用来告知智能体发生了这件事。所以可审计性一直是我们叙事的重要部分，既是为了符合监管要求，也是为了我们的智能体循环。

Yeah, the industry cares about outcomes, but compliance cares about auditability, right? And so our system is such that auditability is by default. Every single action that an agent takes produces a change log of what changed, who changed it, from which part of the system, and when. And this applies not just to agents, by the way. It applies to human actors as well. So if you change something in the UI that affects the client, we'll log that action. So it lets us both get auditability by default, but also powers some of our agentic capabilities, where the same thing that we track like a UI change also could be used to inform the agent that that happened. So auditability has been a big part of our story, both for compliance with regulation, but also for our agentic loop.

代理向人发起提示 Agents prompting people

Host

你在演讲里有一句话很妙：“智能体提示人的次数，比人提示智能体的次数更多。”那么智能体如何决定让谁参与进来，以及它们需要向那个人提供多少上下文，才能让对方完成需要做的事？
