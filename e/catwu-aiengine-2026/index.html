核心观点 · Key points

  • 编码智能体让工程师可以委托实现工作，转而专注于产品品味和商业判断。
    Coding agents let engineers delegate implementation and focus on product taste and business sense.
  • Claude Code 和 Claude Tag 在内部被用来构建自身，Claude Tag 已落地 65% 的产品 PR。
    Claude Code and Claude Tag are used internally to build themselves, with Claude Tag landing 65% of product PRs.
  • 自动模式对长时间运行的任务是安全的；Anthropic 已通过红队测试缓解了提示注入和数据外泄风险。
    Auto mode is safe for long-running work; Anthropic has red-teamed and mitigated prompt injection and exfiltration risks.
  • 通过移除示例和硬性约束，前沿模型的系统提示词缩减了 80%，转而依赖模型判断力。
    System prompts shrank 80% for frontier models by removing examples and hard constraints, relying on model judgment.
  • 评估套件使新模型可以即插即用，并防止代码审查和行为出现回退。
    Eval suites enable new models to be drop-in replacements and prevent regressions in code review and behavior.
  • 内部试用和明确的留存与打磨标准，是每个功能公开发布前的门槛。
    Dogfooding and a clear internal bar for retention and polish gate every feature before public release.

  • 重写现在是好事；代码库就是一份规格说明，有了好的测试套件，重写完全没问题。
    Rewrites are now good; a codebase is a spec, and with a good test suite rewriting is fine.
  • 在提示词中给示例反而可能有害；前沿模型没有示例时更有创造力。
    Giving examples in prompts can hurt; frontier models are more creative without them.
  • 对于外层变更，人类应被移出代码审查循环，完全由 Claude 审查。
    Humans should be removed from the code review loop for outer-layer changes, with Claude reviewing fully.
  • 在提示注入和数据外泄风险上，自动模式比普通人类审查者更安全。
    Auto mode is safer than the average human reviewer for prompt injection and data exfiltration risks.
  • 工具设计更像生物学而非物理学；它是一门艺术，而非确定性科学。
    Tool design is more biology than physics; it is an art, not a deterministic science.
  • 不要自我设限地谈判；让权衡自己证明自己，而不是假设它们真实存在。
    Don't negotiate against yourself; make trade-offs prove themselves instead of assuming they are real.
