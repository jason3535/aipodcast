核心观点 · Key points

  • 验证是智能体最重要的技能：必须能运行代码、测试行为，才能闭环。
    Verification is the most important skill for agents: they must run code and test behavior to close the loop.
  • 工程师变成智能体的管理者，负责搭建环境并将工程标准编码为技能。
    Engineers become managers of agents, setting up the kitchen and encoding engineering standards into skills.
  • 对智能体的信任是逐步建立的；没有信任，无法从单个智能体跳到上千个。
    Trust in agents is built incrementally; you cannot jump from one agent to a thousand without it.
  • 通过 CI、lint 和架构进行硬性约束，远比软性规则或技能更强大。
    Hard enforcement via CI, lints, and architecture is far stronger than soft rules or skills.
  • 全新氛围编程的应用需要尽早建立强护栏，否则代码库会失控。
    Greenfield vibe-coded apps need strong guardrails early, or the codebase spirals out of control.
  • 前期投入 token 进行重构和约束代码，能通过赋能整个团队获得回报。
    Investing tokens upfront to refactor and constrain code pays off by empowering the whole team.

反共识 · Contrarian takes

  • 重写应用通常不被鼓励，但在智能体时代，这可能是正确选择。
    Rewriting your app is often discouraged, but with agents it can be the right call.
  • 完全禁止代码注释：智能体会写历史性、无关的注释，造成误导。
    Ban code comments entirely: agents write historical, irrelevant comments that mislead.
  • 大厂代码质量往往不高；AI 垃圾代码之前，人类垃圾代码早已存在。
    Big tech code quality is often poor; human slop existed before AI slop.
  • 最短路径就应成为最佳路径，因为智能体本来就爱走捷径。
    The shortest path should be the best path, because agents love shortcuts anyway.
  • Rust 严格的编译器比人工审查更可信；只要能编译，大概率就能工作。
    Rust's strict compiler gives more trust than human review; if it compiles, it likely works.
